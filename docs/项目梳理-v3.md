## 2. 核心功能实现度：**全部实现，无「声明 ≠ 实现」残留**

v1 梳理发现的 13 项死配置/死代码（§7.2 清单）在 v2/v3 批次后**全部清零**：
- `fix_loop.*` 三键、`stages.review.dimensions`、`budget.on_exhausted`、`visibility.progress` → 全部扩展为多值枚举并接线（`grep 'z.literal' src/config/schema.ts` 仅剩注释）；
- `plan_protocol`、`max_parallel_tasks`、`STEP_GUARDS`、空壳 hook、死 API → 删除；
- `review.input_token_budget` → 接线（三级裁剪）；`lint` 命令 → 接线。

新增 6 个配置语义（C1–C6）均有两种取值的差异单测（`test/refactor-v3.test.ts` 等）。

## 3. 主体链路贯通性：**全链路贯通，无断链**

```
用户输入 → handleUserInput（门禁/预检/排队）→ task/launch → PLANNING
  → (审计门 runAuditGateIfPending ⇄ 审计员子代理) → plan/ok → EXECUTING
  → turn 驱动（needReplan / exec/fail / steps 超限 / quick channel / exec/ok）
  → REVIEWING → dispatchReviewer（单片/分片）→ routeVerdict
  → review/pass:MISS 回执行 / fail-exec 修复回路 / fail-plan 重规划 / pass → DONE
  → 全程 accountUsage 记账 + 熔断 + 快照落盘 → settle 清理 → 队列交接
```

每一环都有真实调用点与测试背书（fsm 28 例覆盖全迁移路径；engine-turn 10 例覆盖 turn 驱动；refactor-v2/v3 28 例覆盖派发/记账/门禁/新语义）。异常路径（预算耗尽、熔断、用户取消、模型 hard-fail、复核死锁、审计 fail-open）全部可达终态，`ci-checks` 的「终态可达 + 零成本环 + 回退链 ≤2 + 变体行可达」6 项不变量机械保证。
