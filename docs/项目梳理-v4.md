## 2. 本轮增量发现（v4 批后全部闭环，处置见 `重构方案-v4.md` 与 CHANGELOG 0.4.0）

### F1（P1 · 声明 ≠ 实现）`budget.count_passthrough` 是死配置

- **声明**：`config/schema.ts:132` `count_passthrough: z.boolean().default(false)` 注释「ADR #27 (revised)」——配置为 `true` 时透传消耗计入每日硬上限。
- **实测**（grep 全库）：
  - 引擎对透传会话只调用 `ledger.observePassthrough()`（`engine/accounting.ts:96`），该函数**只累加 `daily.passthrough`，从不查 limits**；
  - 全库**不存在** `debit(..., 'passthrough', ...)` 调用；`ledger.ts:145` 的 `againstDaily = countPassthrough` 分支只在 `stage === 'passthrough'` 的 debit 路径有效——而该路径是死代码（`ledger.ts:159` `void againstDaily` 自证）。
- **后果**：用户配置 `count_passthrough: true` 期望透传也受日限额约束，实际完全无效——与 v1 发现的 `plan_protocol` 同类问题，但藏在 ADR #27 的「revised」注释里更有迷惑性。
- **处置（需用户决策，两选一）**：
  - **① 实装**（推荐）：`accountUsage` 透传分支在 `count_passthrough=true` 时改走 `ledger.debit(sessionId, 'passthrough', ...)`，`debit` 的 passthrough 分支按 `countPassthrough` 决定计入 `daily.orchestrated`（达到日限额返回 `ok:false`，透传侧不触发任务中止、仅停止记账透传——透传没有 FSM 任务可中止）；`false` 维持现状。附单测。
  - **② 删键**：README/CHANGELOG 声明「透传仅观测、永不计入限额」，删 schema 键与 `againstDaily` 死分支。

### F2（P2 · 一致性）机械验证摘要丢失 lint

- `engine/prompts.ts:36-41` `mechSummary`（复核 prompt 的「机械验证」行）与 `:67-73` `buildFixDirectiveFromMechanical`（`review/pass:MISS` 的修复指令）都只拼 `compile`/`tests`，不含 v3 已实装的 `lint` 结果。lint 配置用户的复核员看不到 lint 结论、机械漏判修复指令缺 lint 输出。

### F3（P2 · 可测性）时间源不贯通

- `fsm.ts:187` `updatedAt = Date.now()`、`fsm.ts` 构造器 `startedAt`、`ledger.ts`（`dayKey`/entry `at`）、`registry.prune` 全部直接 `Date.now()`，而引擎的 `clock` seam 只覆盖熔断/预算预检/executionLog。时钟替身冻结不了 FSM 时间戳与台账日期，跨天/时区行为无法确定性测试。建议：`OrchestratorTask` 构造器接受可选 `now?: () => number`，ledger 同理（默认 `Date.now`，引擎注入 clock）。

### F4（P2 · 资源）`budget.json` 的 `daily` map 无界增长

- 每天一个 key，长驻宿主/长期安装永不清理（v1 只对 `tasks` 与 ledger 做了修剪）。方案：`pruneTasks` 时顺带清理 30 天前的 daily 记录（保留窗配置化可选，先固定值）。

### F5（P3）health 半开窗口允许多并发探测

- `health.ts:58` `at >= halfOpenAt` 后对所有请求返回 false（放行），「允许**一次**探测」的语义未强制——并发下多个请求同时充当探测。影响小（成功即清零、失败即重关），文档化或加 in-flight 探测标志均可。

### F6（P3）降级链丢 provider

- `model-router.ts:51` 降级链遍历时 `provider = undefined`（注释「family default provider」）——`fallback_chain` 配置跨 provider 模型时绑定会静默丢失 provider。与 effort 家族映射同样的隐式约定；README 已写 fallback_chain 是「模型列表」，但行为应在 README「已知限制」明示（或支持 `provider::model` 语法，属新功能，不建议本批做）。

### F7（P3）`routeVerdict` 死分支

- `protocols/review.ts:68-72` `mechanicalPass === false` 分支返回的 `note: 'mechanical-miss'` 无消费者（实际路由靠 `flags.mechanicalFailedAfterPass` + 表内守卫选择 `review/pass:MISS`）。简化函数签名或删除 note。

### F8（P3）`/orch set` 的冗余全局重算

- `engine/commands.ts:82` `set` 后调用 `applyOverrides()`（重算**全局**层）——会话覆盖实际在 `sessionEffective()` 与路由 `override` 参数处生效，该调用不仅无效还误导读者以为会话覆盖被合并进了全局（恰好违反「全局与会话绝不混入」的架构约束）。删除。

### F9（P2 · 门禁缺口）缺少「配置键必须被消费」不变量

- v1 方案 §5.2 就提议 ci-checks 第 6 项：扫描 schema 叶子键，要求在 src 其他文件被消费。若当时落地，F1（count_passthrough）会被自动捕获。现在 ci-checks 已有 6 项不变量，第 7 项应补上（排除 settings 透传键与 literal 策略键的白名单机制）。

### F10（P3 · 体验）设置 UI 无 `budget.pricing` 编辑器

- v3 的未计价模型告警引导用户「在补丁配置中设置 budget.pricing」，但设置卡片没有该字段（grep web/src/client.js 无 pricing）——用户必须手改 YAML。加一个「模型单价表」编辑器可闭环 P0-03 的护栏体验；不改也不影响正确性。
